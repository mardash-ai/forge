# Platform release feed

<!-- Static reference doc — update when the feed schema or workflow changes. -->

Every Forge release (GitHub tag `vX.Y.Z`) publishes three files as **GitHub release assets** that
together form the **platform release feed** — the machine-readable contract downstream consumers
(forge-site, forge-os, forge-starter) use to track what the platform exposes and how it changed
between releases.

---

## Assets published per release

| File | Description |
| --- | --- |
| `platform-model.json` | Full platform model snapshot for this tag — capabilities, resource types, event catalog, error taxonomy, route tables, and **CLI surface**. |
| `platform-changes.json` | Semantic diff of this model vs. the previous semver tag, in the `platform-changes/v1` schema. |
| `platform-changes.md` | Human-readable Markdown rendering of the same diff, suitable for a GitHub release body. |

---

## Fetching a specific release

```bash
# Full model for a pinned tag:
gh release download v1.58.0 --repo mardash-ai/forge --pattern 'platform-model.json'

# Diff vs. the previous tag:
gh release download v1.58.0 --repo mardash-ai/forge --pattern 'platform-changes.*'
```

Or via the HTTPS download URL (no auth required for public repos):

```
https://github.com/mardash-ai/forge/releases/download/v1.58.0/platform-model.json
https://github.com/mardash-ai/forge/releases/download/v1.58.0/platform-changes.json
https://github.com/mardash-ai/forge/releases/download/v1.58.0/platform-changes.md
```

## platform-model.json schema

Schema ID: `https://forge.build/platform-model/v1`

```jsonc
{
  "$schema": "https://forge.build/platform-model/v1",
  "version": "1.58.0",        // semver — matches the git tag
  "capabilities": [...],       // every Capability slug + input_schema + endpoint
  "resource_types": [...],     // closed set of Resource type names
  "event_catalog": [...],      // closed set of Event type names
  "error_taxonomy": [...],     // ForgeError variants with retry semantics
  "route_tables": { ... },     // inline + module routes for control + data plane
  "cli_surface": [...]         // every `forge` verb, its args, and the route it calls
}
```

The model is **committed** in the forge repo at `platform-model.json` and regenerated by
`npm run generate:platform-model`. The CI drift guard (`ci.yml` → "Platform model drift check")
re-runs the generator on every PR and fails if the committed file is stale.

### CLI surface

`cli_surface` is an array of verb entries:

```jsonc
{
  "verb": "forge build",
  "description": "Run a reproducible build (Build)",
  "route": "POST /capabilities/build",   // HTTP method + path, or "local" for in-process
  "args": [
    { "flag": "--app <app>", "required": true,  "description": "application name" },
    { "flag": "--platform <platform>", "required": false, "description": "target platform" }
  ]
}
```

Keep `cli_surface` in sync with `src/cli/index.ts`. The drift guard catches any version bump
where `platform-model.json` doesn't match what the generator produces.

## platform-changes.json schema

Schema ID: `https://forge.build/platform-changes/v1`

```jsonc
{
  "$schema": "https://forge.build/platform-changes/v1",
  "from_version": "1.57.0",
  "to_version":   "1.58.0",
  "empty": false,            // true when models are identical (explicit, never an error)
  "capabilities": {
    "added":   [{ "slug": "new-cap", ... }],
    "removed": [{ "slug": "old-cap", ... }],
    "changed": [{ "slug": "changed-cap", "changed_fields": ["description", "events"], ... }]
  },
  "resource_types": { "added": ["NewType"], "removed": ["OldType"] },
  "event_catalog":  { "added": ["NewEvent"], "removed": [] },
  "error_codes": {
    "added":   [],
    "removed": [],
    "changed": [{ "code": "internal_error", "changed_fields": ["description"], ... }]
  },
  "routes": {
    "control_plane": { "added": ["GET /new-path"], "removed": [] },
    "data_plane":    { "added": [], "removed": [] }
  },
  "cli_verbs": {
    "added":   [{ "verb": "forge new-cmd", ... }],
    "removed": [{ "verb": "forge old-cmd", ... }],
    "changed": [{ "verb": "forge changed-cmd", "changed_fields": ["route"], ... }]
  }
}
```

An **empty diff** (`"empty": true`) is represented explicitly with zeroed arrays — it is not an
error. The first release after a repo bootstrap has `"from_version": "(none)"` and all items appear
in the `added` arrays.

## Generating the diff locally

```bash
# Between two tags:
npm run diff:platform-model -- v1.57.0 v1.58.0

# Between two local files:
npm run diff:platform-model -- --from-file old-model.json --to-file new-model.json

# First release (no previous tag):
npm run diff:platform-model -- none v1.58.0
```

Outputs `platform-changes.json` and `platform-changes.md` in the working directory.

## CI integration

`publish-image.yml` has a `release-assets` job (needs the `test` gate) that:

1. Checks out the full git history (`fetch-depth: 0`) so `git show <prevTag>:platform-model.json` works.
2. Finds the previous semver tag via `git tag --sort=-v:refname`.
3. Runs `npm run diff:platform-model -- <prevTag> <currentTag>`.
4. Creates (or updates) the GitHub release for the tag via `gh release create`.
5. Uploads `platform-model.json`, `platform-changes.json`, and `platform-changes.md` via `gh release upload --clobber`.

The job only fires on `push: tags: v*` events, not `workflow_dispatch`.
